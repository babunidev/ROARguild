# Roadmap

This roadmap describes the order in which the project can mature. It is not a dated delivery schedule. Items remain proposals until explicitly approved.

## 0. Establish the project foundation

**Status: Complete**

- [x] Create the public repository.
- [x] Establish the initial documentation structure.
- [x] Record the current game focus and distinguish decisions from proposals.
- [x] Curate the current community direction and document the Eldgrim concept.
- [x] Complete the initial review and refinement of the project documents.

## 1. Settle the guild identity and foundations

**Status: Open / developing**

- [x] Establish **Amberhearth** as the Alliance RP guild name; retain ROAR as the wider project identity.
- [x] Confirm Amberhearth’s direction as an Alliance roleplaying fellowship within ROAR.
- [x] Adopt the guild charter and community expectations.
- [ ] Define practical responsibilities, including any bank stewardship committee.
  - Amberhearth has no guild bank yet. Bank custodians and dispute reviewers have not been appointed. The founder is currently the only high-ranking member. See [Eldgrim’s operating procedures](https://github.com/babunidev/eldgrim/blob/main/governance/OPERATING-PROCEDURES.md#quests-fires-and-bank-stewardship) for the planned workflow.
- [x] Establish recruitment and onboarding for new members.
  - In-game recruitment is active. The founder posts in chat, and interested players whisper for an invite. Members have joined this way. Discord onboarding uses the [Character Forge](https://github.com/babunidev/eldgrim/blob/main/bot/README.md).
- [x] Set up the Discord and in-game channels Amberhearth needs to welcome new members.
  - The current channels are ready for members to use and can evolve as the fellowship grows.

## 2. Prepare the first community

**Status: In progress**

- [x] Establish the initial Alliance roleplaying presence in World of Warcraft Forever.
  - Amberhearth is founded, has recruited members in-game, and is ready to welcome more players.
- [x] Establish the basic setup for day-to-day guild operations.
  - The founder confirmed that the current setup is sufficient and that Eldgrim is handling Discord tasks through the [server bot](https://github.com/babunidev/eldgrim/blob/main/bot/README.md).
- [ ] Prepare a simple introduction for new and returning players.
- [ ] Keep participation voluntary and avoid creating obligations before they are needed.

## 3. Develop shared activities

**Status: Developing**

- [ ] Explore social gatherings and spontaneous adventures.
- [x] Establish Sunday road bonfires as the planned community tradition; plan and record individual regional gatherings separately.
- [ ] Decide whether recurring events are useful and, if so, agree on their format and cadence.
- [ ] Make room for roleplay, exploration, dungeons, raids, and PvP according to member interest.

## 4. Develop community tools

**Status: Developing concept**

- [x] Establish the name **Eldgrim** and its high-level storytelling role; continue refining voice and public presentation in the separate Eldgrim repository.
- [ ] Define the full architecture: always-online Discord bot and SQL database on the server, with a periodically active AI agent on the creative's computer.
- [ ] Define player registration, multiple-character identity, roleplaying character sheets, keyword categories, and the internal 0–100 standing score.
- [ ] Specify Discord activity logging, daily AI processing, raw-log handling, and the persistent-memory boundary.
- [ ] Resolve transparency, consent, access, retention, correction, and deletion rules before member-data collection is implemented.
- [ ] Define the addon data supplied by characters and selected event observers, including the daily guild bank snapshot.
- [ ] Specify the fire-themed quest, screenshot-and-witness verification, reward, and guild bank committee workflows.
- [ ] Define the Eldgrim's delegated rank, role, moderation, timeout, and critical-exception permissions.
- [ ] Decide how manual in-game rank synchronization and character verification will work.
- [ ] Decide where the bot implementation will live and verify each integration against the World of Warcraft Forever environment.

## 5. Review and grow carefully

**Status: Future possibility**

- [ ] Review what works as the community and tools develop.
- [ ] Consider whether other factions or rulesets should have independent ROAR chapters.
- [ ] Let future chapters be shaped by the people who take responsibility for them.
- [ ] Revisit the roadmap as actual experience replaces assumptions.

## Roadmap review

During the November 2026 review, I confirmed that the initial documentation review was complete and that Amberhearth’s direction was settled. ChatGPT (Codex, GPT-6) reviewed the roadmap and recorded those confirmations.

## Out of scope for the initial launch

- A multi-client or multi-ruleset launch.
- A mandatory progression, attendance, or raiding structure.
- Treating future chapters as already operating.
- WoW addon source code and addon implementation, which belong in separate repositories.
- Claiming that a community tool is implemented or operational before it has been built and verified.
